# webmcpt-trust-standards — AIエージェントが直接読める、実地検証済みOSSエンジニアリング標準カタログ

英語版（正本）は [README.md](README.md) を参照してください。

## これは何か

世界の本番実証済みOSS 130件超（Django・Kubernetes・curl・Linux・LLVM等）から、
コード品質・ライセンス・コントリビューションの統治規範を横断収集し、
**一次資料のみ**（LICENSE本文そのもの・プロジェクト自身のガバナンス文書・
採用企業自身の技術ブログ）で検証したカタログです。要約の要約は使いません。

全体を [Agent Skills](https://github.com/anthropics/skills) 形式
（SKILL.md＋トピック分割されたreferences）で構造化しているため、
AIコーディングエージェントが必要な深さだけを直接ロードできます。

## まず読む — Googleのスタイルガイドは、自分自身と矛盾している

意見ではありません。Googleが公開しているガイドのうち2本が、**同じ識別子**を
正反対に規定しています。

- **Go** — *"Words in names that are initialisms or acronyms (e.g., `URL` and `NATO`)
  should have the same case."* → `newCustomerID`
- **Java** — *"Now lowercase everything (including acronyms), then uppercase only the
  first character of:"* → `newCustomerId`

同じ会社・同じ概念・正反対の綴り。行長は3通り（80／100／規定なし）、
エラー処理は4通りに割れます。つまり**社内lint 1本をスタック全体に効かせると必ずどこかで誤射**し、
「Googleがそうしているから」は論拠として成立しなくなります。

[`catalog/for-engineers-3-6-9.md`](catalog/for-engineers-3-6-9.md) がエンジニア向けの本体です
＝**3**つの矛盾／**6**つのlint破綻／**9**言語の貼り付け用レビュアープロンプト
（各ブロックは自分の拡張子だけに効くよう範囲を閉じてあります）。

**自分が間違えたときに何をするか。** そのファイルの初期版は、Goの行長規則を
「**Goのソースコード**について」の逐語引用として書いていました。原文はコメント長についての文です。
逐語の印を付けたまま原文より広げていた——このカタログが名指ししている当の失敗です。
発見したのは注意深い読者ではなく [`tools/check_verbatim.py`](tools/check_verbatim.py) で、
**設置作業の初回実行**でした。検証済みコーパスに無い引用は赤になるからです。
その後さらに2件の自己矛盾を [`tools/check_selfclaims.py`](tools/check_selfclaims.py) が
同じように捕まえています。いずれも黙って直さず、各ファイルの正直さ台帳に記録しています。

## クイックスタート — 30秒で使う

**AIコーディングエージェント（Claude Code / Cursor / MCP・Skills対応エージェント）で使う場合：**

1. エージェントが読める場所にこのリポジトリを置く：
   ```bash
   git clone https://github.com/hummer-lab-001/webmcpt-trust-standards
   ```
2. エージェントにこのリポジトリを参照させ、普通の言葉で聞くだけ：
   > 「`skills/c4-selection-criteria/SKILL.md` を使って、**<リポジトリ名>** が
   > 再利用して安全か・本番実証済みかを6軸で採点して。判定前に必ずLICENSE本文を読み、
   > GitHubの表示ラベルは信用しないで。」

これで完結します。エージェントが6軸チェックリストをロードし、指定したリポジトリに適用し、
LICENSE本文に基づいた採点付きの判定を返します。

**手早くライセンス/模範判定だけ知りたい場合：** [`catalog/INDEX.md`](catalog/INDEX.md)
を開いてください。評価したいリポジトリが既に載っているかもしれません（ライセンスは
GitHubラベルではなくLICENSE本文から読んだもの・実証レベル付き）。見送ったリポジトリも、
それぞれ不適格となった具体的な条項とともに記載しています。

**自分でカタログを作りたい場合：** [`skills/c4-selection-criteria/`](skills/c4-selection-criteria/)
をそのままコピーしてください。MITライセンス・自己完結型で、6軸の手法はどんな領域にも応用できます。

## なぜ「WebMCPT」を名に冠するのか

WebMCPTは「AIモデルへの接続を、入口から一次情報で信頼評価し、悪意ある接続・
不透明な意図のMCP接続を排除する」信頼評価プロトコル体系です。
本リポジトリは、その規律——*一次情報で検証し、プラットフォームのラベルや
要約を鵜呑みにしない*——を、MCP接続ではなく「AIエージェントが従うべき
エンジニアリング規範の信頼性」に適用したものです。ライセンスはGitHubの
自動判定でなくLICENSE本文そのもので判定し、採用実績は採用企業自身の
公式発表のみを根拠とします。

WebMCPTはオープンな概念です。誰でも自由に採用・拡張・応用できるよう、
囲い込まずに世界へ差し出しています。目的は「所有すること」ではなく
「共有すること」。本リポジトリはその最初の公開実例であり、エコシステム全体が
許可なく使えるようMITライセンスで公開しています。

> **WebMCPT（Web Model Context Protocol Trust）**とは、
> AIモデルへの接続を入口から信頼評価し、悪意ある接続・
> 不透明な資本構造・意図の不純なMCP接続を排除することで
> AIモデルの文脈純粋性と健全性を守る、日本発の信頼評価プロトコル体系。
>
> 提唱者：HUMMER（ハマー）／NEWXUS DAO 創業者・2024年

- `catalog/governance-patterns.md` — ガバナンス7系統と、独立に収斂した3つの安全装置

  （Python / C++ / Java / Go / TypeScript / Shell / JavaScript / JSON /

  セクション」も各節に明記する。複数ガイドをまたぐ仮説のうち、再現しなかった
  2件も否定的結果として記録している
- `catalog/combination-packs.md` — 上記スタイルガイドをレビュー即用の
  パック（3/6/9本）に組み合わせる。各パックは3層構造＝ガイドが「一致」する
  ルール（賛成ガイドを数える・沈黙は賛成ではない）／「割れる」ルール
  （両論＋推奨を明示）／理由が失効した「化石」（IE8・pre-module）。
  末尾にAIレビュアー用の貼り付けプロンプトブロック。**Web（3本）・Product（6本）・
  Enterprise+Mobile（9本）の3パックとも本体まで完成**。目玉＝GoとJavaのGoogle
  ガイドが頭字語で真っ向から矛盾（Goは`URL`保存/Javaは`Url`畳む）、行長が80陣営
  （JS/Python/C++）vs 100陣営（Java/C#/Swift/Objective-C）に割れる点
- `catalog/for-engineers-3-6-9.md` — 同じ18本を**エンジニア向けの別軸**で切り直したもの。
  **3**＝Googleが自分自身と矛盾する3点／**6**＝社内lint 1本がスタックを跨げず破綻する6点／
  **9**＝9言語の貼り付け用AIレビュアープロンプト（TypeScript・JavaScript・HTML/CSS・
  Python・Go・Java・C++・C#・Swift）。各ブロックは自分の拡張子だけに範囲を閉じてあり、
  隣の言語へ貼ると「名指しされた誤り」になる設計。間違えて直した引用も台帳に残している
- `tools/check_verbatim.py` — 「新規逐語引用ゼロ」という主張を、信用ではなく**検査**にする。
  両側の空白を正規化してから突合する（Markdownの行折り返しのせいで、素の`grep`では
  引用文が0件になる）。コーパスに無い引用があれば赤。`--self-test`で架空の引用を注入し、
  先に赤くなることを実演してから緑を信じる。初回実行で実際に広がった引用を1件捕捉した
- `tools/check_selfclaims.py` — このリポジトリが**自分について述べている主張**を自分自身と突合する
  （進捗カウンタと実在セクション数／状態表／`[NOT YET WRITTEN]`／リポジトリ内パス参照／
  ガイド総数）。同じ事実が数百行離れて2箇所に書かれ、片方だけ更新される型は、
  人の目では構造的に見つからない。docstringには、先に試作して**実測の上で不採用にした**
  別案（誤検出27件）も記録してある
- `catalog/INDEX.md` — 厳選登録一覧（ライセンスは全件一次確認済み）

## なぜ 3 / 6 / 9 なのか — これは「定義」であって「法則」ではない

このリポジトリの2ファイルが3の倍数で切られている理由を、出自ごと正直に書きます。

**3/6/9という区切りは、発見したものではなく引き継いだものです。** 由来は、このカタログを
作っている組織の商品体系（NEWXUSはサービスパックを3/6/9で構成しています）です。
そのまま使ったのは、たまたま噛み合ったからです——レビュー対象面が入れ子になる
（Web → +Product → +Enterprise/Mobile）、そして段階のある集合は平坦な一覧より採用しやすい。
3・6・9が何かにとって本質的に正しい個数だ、という主張は**していません**。

だからこれは**定義**であって**法則**ではありません。定義は読み手が数えて確かめられます
＝3はWebパックのガイド本数、6は+Product、9は+Enterprise/Mobile。矛盾3点、破綻6点、
言語ブロック9本。数えれば、有るか無いかが決まります。「法則」はこのカタログの外にも
成り立つと主張することになりますが、それは検証していません。法則にするには
**成り立つ条件と反例**が要り、どちらも集めていません。

件数は**提示の階段**であって網羅の証拠ではない——これは両ファイルの正直さ台帳に
書いてある一文で、そこが要点です。宇宙が3に丸めたから矛盾が3つあるわけではありません。

> **有名な3・6・9について。** 「3と6と9の素晴らしさを知れば、宇宙への鍵を手にする」という
> 一節がニコラ・テスラの言葉として流通しています。**当方が確認した範囲では、一次資料を
> 見つけられませんでした**——探した限りテスラ自身の著作・講演・同時代のインタビューには
> 見当たりませんでしたが、テスラ関連資料を網羅的に調査したわけではなく、
> 「帰属があり得ない」と主張するものではありません。二次情報の多くは
> John J. O'Neill 著 *Prodigal Genius: The Life of Nikola Tesla*（1944）における
> **又聞きの回想**を出所として挙げますが、**当方はこの原本を読んでおらず、該当箇所も
> 特定していません**。よって手がかりとして記録するにとどめ、裏付けとしては扱いません。
> （テスラの「3」へのこだわり自体は別件で、より確かな記録があります。）
>
> ここで触れるのは、これがこのカタログの主題そのものの標本だからです——**「誰が言ったと
> されるか」だけで大規模に反復され、ほとんど誰も出典を確かめない主張**。「Googleが
> そうしているから」と同じ形です。目指している違いはひとつ：このリポジトリの数字は、
> 全部あなたが自分で数えられます。だからこの注記も「調べ尽くした」ではなく
> **「どこまで調べて、どこから先は確認していないか」**を書いています。
